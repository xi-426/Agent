# RAG 参数证据与选择过程

本文只记录当前代码实际使用、且能够用实验结果解释的参数。

## 1. 结论

当前线上检索配置：

| 参数 | 当前值 | 证据 |
|---|---:|---|
| 单文件上限 | 10 MB | 产品级资源保护上限，不是检索效果参数 |
| 批量文件数 | 20 | 产品交互与资源保护上限 |
| 批量总大小 | 50 MB | 产品交互与资源保护上限 |
| 切片长度 | 800 字符 | 17 组切片方案对真实语料的离线比较结果 |
| 重叠长度 | 120 字符 | 同上 |
| 向量维度 | 1024 | bge-m3 模型输出维度，不能随意修改 |
| 检索 Top-K | 8 | 校准集 K 曲线首次达到最高召回的平台点 |
| 最大余弦距离 | 0.3495513922998467 | 校准集候选阈值搜索结果 |

这些数值不是行业统一标准。切片参数、Top-K 和距离阈值只对当前 12 份学校资料、当前 bge-m3 模型和当前标注集负责；更换语料或模型后应重新评测。

## 2. 数据集怎样构建

- 语料：12 份真实学校通知、办法、说明和申请表。
- 文档处理后：44 个切片。
- 人工标注问题：48 条。
- 可回答问题：36 条，每条标注一个或多个正确文档/切片。
- 无答案问题：12 条，用于检查系统能否拒答。
- 校准集：32 条，其中 24 条可回答、8 条无答案。
- 隔离测试集：16 条，其中 12 条可回答、4 条无答案。

校准集用于选参数，测试集只用于最后报告结果。这样可以减少“在测试题上调到最好，再拿同一批题证明自己”的数据泄漏。

## 3. 切片 800/120 怎样得到

项目不是直接认定 800/120 最优，而是先根据真实文档的段落和句子长度构造 17 组候选组合，对每一组重新执行：

```text
原文提取
→ 清洗
→ 按候选 chunkSize/chunkOverlap 切片
→ bge-m3 向量化
→ pgvector 检索
→ 用人工相关标注计算检索指标
```

最终选 800/120，是因为它在当前语料上兼顾了来源召回、切片数量和上下文冗余。它不是理论最优值；文档结构变化后需要重新实验。

## 4. 当前检索排序

pgvector SQL 按余弦距离从小到大排序，当前链路直接使用这个顺序：

```text
问题向量化
→ 在当前知识库的 READY 文档中按余弦距离升序检索
→ 保留距离不超过阈值的切片
→ 取前 Top-K 条作为生成上下文
```

如果以后加入 BM25 + RRF 或 Cross-Encoder，应使用相同测试集做对比；只有指标稳定提升且延迟可接受时才保留。

## 5. Top-K=8 怎样得到

固定切片和向量模型后，在校准集统计 `K=1..20` 的原始向量检索命中率：

| K | 校准集有答案题来源命中率 |
|---:|---:|
| 1 | 83.33% |
| 2～7 | 95.83% |
| 8～20 | 100% |

K=8 是第一次达到最高召回的平台点。继续把 K 调大，没有增加校准集来源命中，却会增加 Prompt 长度、重复资料和模型干扰，因此选择满足最高召回的最小 K。

这不是说任何知识库都应该使用 8。文档增加或问题分布改变后，要重新画 K 曲线。

## 6. 距离阈值 0.3496 怎样得到

余弦距离越小越相似。阈值承担“回答还是拒答”的门控作用：

- 阈值太小：规则严格，可回答问题容易被误拒绝。
- 阈值太大：规则宽松，无答案问题可能被误放行。

项目在校准集上收集每个问题的最近切片距离，把真实出现过的距离作为候选分界点，逐一计算：

- 决策准确率；
- 无答案误接受数；
- 有答案误拒绝数。

选择顺序是：优先减少无答案误接受，再比较整体决策准确率和有答案召回，最终选出 `0.3495513922998467`。配置和页面中显示为约 `0.3496`。

## 7. 独立测试集结果怎样解释

使用校准集选出的 `Top-K=8` 和阈值约 `0.3496`，在 16 条隔离测试题上得到：

| 指标 | 结果 | 含义 |
|---|---:|---|
| Hit@8 | 11/12 = 91.67% | 12 条可回答题中，11 条的人工正确来源进入前 8 条 |
| 门控决策准确率 | 15/16 = 93.75% | 16 条题中，15 条被正确判断为回答或拒答 |
| 无答案误接受 | 0/4 | 4 条无答案题全部被拒答 |
| 有答案误拒绝 | 1/12 | 12 条可回答题中有 1 条被阈值误拒绝 |
| MRR@8 | 0.8611 | 正确来源首次出现位置的倒数均值 |
| nDCG@8 | 0.8750 | 同时考虑相关来源位置与排序质量 |
| Context Precision@8 | 0.4452 | 前 8 条中人工相关来源所占比例 |

Hit@8 和门控准确率不是“答案正确率”。前者测检索来源是否命中，后者测系统是否应该放行生成；它们都没有证明大模型生成内容完全正确。

## 8. 面试时可以直接这样说

> 我没有把 Top-K 和距离阈值当成行业固定值。项目使用 12 份真实学校资料构建 48 条人工标注问题，其中 32 条用于校准，16 条只用于最终测试。切片先比较了 17 组方案，选出 800/120；固定切片后统计 K=1 到 20 的召回曲线，K=8 是校准集首次达到最高召回的平台点，所以选择满足召回的最小 K。距离阈值则根据可回答和无答案问题的最近余弦距离搜索得到约 0.3496。独立测试集 Hit@8 为 11/12，回答/拒答判断为 15/16。当前正式链路就是 pgvector 余弦距离 Top 8 加距离门控。

## 9. 必须主动说明的边界

- 48 条属于小规模固定离线评测，不代表普遍性能。
- Hit@8 不是答案准确率。
- 当前没有对 DeepSeek 生成答案做大规模自动事实评分。
- 当前阈值绑定现有语料、切片方式和 bge-m3；新增大量不同类型文档后应重跑校准。
- HNSW 是加速近似最近邻搜索的索引；当前数据量很小时性能优势不明显，项目价值主要在完整链路验证。
