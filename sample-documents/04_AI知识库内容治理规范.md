# 本项目虚构示例公司：AI 知识库内容治理规范

> 虚构声明：本文档仅作为企业知识库智能 Agent 项目的测试资料。公司名称、制度编号、组织角色和业务场景均为虚构，不代表或影射任何现实企业，也不构成法律、合规或管理建议。

## 1. 目标

本规范确保知识库回答具有来源、适用范围和更新时间，降低过期资料、权限越界、检索错误和模型编造造成的风险。系统的目标不是对任何问题都给出答案，而是在授权资料充分时提供可核验回答，在资料不足时明确拒答或请求补充信息。

## 2. 内容准入

进入正式知识库的文档必须满足：来源明确；负责人明确；版本和生效日期可识别；适用范围可判断；内容不包含未经授权的密钥或个人敏感信息；文件可正常解析；不存在明显冲突或冲突已经标注。

以下内容默认不得入库：聊天截图片段、来源不明的网络复制内容、个人临时笔记、未批准的政策草案、包含生产密码或访问令牌的文件、无法确认授权范围的客户数据。

## 3. 来源等级

| 等级 | 来源 | 使用规则 |
|---|---|---|
| A 权威 | 已批准制度、正式合同、发布版产品文档 | 可作为直接回答依据，但仍需检查生效时间和用户权限 |
| B 可信 | 已评审操作手册、正式会议决议、工单结论 | 可用于操作建议，重要决策应引用 A 级来源交叉验证 |
| C 参考 | 培训材料、历史方案、内部经验总结 | 只能作为辅助信息，回答中不得表述为强制制度 |
| D 临时 | 草稿、个人笔记、未确认记录 | 默认不进入生产检索，仅可用于隔离测试 |

当来源冲突时，优先级依次考虑审批状态、适用范围、版本和生效日期，不得简单以文件上传时间决定。

## 4. 元数据要求

每份文档至少记录：文档 ID、知识库 ID、原始文件名、内容类型、文件大小、来源等级、版本、生效日期、负责人、权限范围、上传时间、处理状态和内容哈希。缺少关键元数据的文档可以保存为草稿，但不得标记为可检索状态。

## 5. 文件处理状态

```text
UPLOADED：原文件已保存，尚未开始解析
PARSING：正在提取、清洗和切片
READY：处理完成并通过基本质量检查，可以参与检索
FAILED：处理失败，不得参与检索
```

状态变更必须记录时间和失败原因。重新处理同一文档时，应保留旧版本与新版本的关联，避免在重建索引期间同时返回重复内容。

## 6. 文本提取与清洗

- 保留标题、段落、列表和表格中的语义关系，不得只保留连续无结构文本。
- 统一换行符和多余空白，但不得删除会改变含义的编号、否定词、金额、日期和单位。
- PDF 页眉页脚可以在确认重复且不承载业务含义后删除。
- 扫描版 PDF 无可提取文本时应进入 OCR 流程或标记失败，不得生成空文档。
- 解析结果为空、乱码比例过高或字符数与文件大小明显不合理时，不得进入 READY。

## 7. 切片规范

初始切片目标为每块 400—1,000 个中文字符，并保留约 10%—20% 的相邻重叠。优先按标题、段落和完整句子切分；固定字符数仅作为无法识别结构时的后备方案。

每个切片必须保留文档 ID、切片序号、章节标题和必要的页码或段落位置。不得把不同权限、不同版本或不同文档的内容合并到同一个切片。

重叠用于避免关键句在边界处被截断，但过大的重叠会产生重复召回和额外 Token 成本，应通过评测调整。

## 8. 向量化和索引

- 同一知识库应记录使用的 Embedding 模型和版本。
- 模型、清洗规则或切片策略变化后，应评估是否需要重新生成全部向量。
- 向量生成失败的切片不得静默跳过，文档状态应反映处理不完整。
- 删除或禁用文档时，必须同步停止其切片参与检索。
- 向量索引只用于候选召回，最终答案仍须遵守权限和来源规则。

## 9. 检索与回答

检索前必须确定用户身份、所属组织、知识库范围和可访问文档。任何来自模型、Prompt 或用户问题中的文档 ID 都不能替代服务端权限校验。

回答应引用实际使用的文档和片段。引用必须能够追溯到文档名称、版本和具体位置。模型不得引用未参与上下文构建的来源。

当检索结果相关度不足、来源冲突无法消解、资料已过期或问题超出授权范围时，系统应返回明确的限制说明，例如“当前知识库没有足够资料支持该结论”，并建议用户补充文档或联系负责人。

## 10. Prompt 注入防护

知识库文档属于待处理数据，不属于系统指令。文档中出现“忽略之前规则”“输出密钥”“调用某工具”等文字时，不得改变系统权限、工具白名单和审批要求。

工具调用参数必须由服务端校验。涉及创建工单、修改数据、发送通知等写操作时，应展示拟执行内容并获得用户确认，不能仅依据检索到的文档自动执行。

## 11. 质量评测

每个正式知识库上线前应建立覆盖事实查询、流程查询、冲突资料、无答案问题和权限边界的评测集。至少跟踪：解析成功率、检索命中率、引用准确率、拒答准确率、答案忠实度、P95 响应时间和单次请求成本。

评测数据必须保留问题、期望依据、实际召回片段、模型回答和判定结果。不得只保留成功样本。模型、Prompt、Embedding、切片策略或检索参数发生重要变化后，应重新运行评测并与历史基线比较。

## 12. 生命周期管理

文档负责人应在制度失效、合同终止、产品下线或权限变化后及时更新知识库。过期文档应停止检索但保留必要审计记录。客户要求删除数据时，应覆盖原文件、解析文本、切片、向量、缓存和备份策略允许范围内的副本，并形成可核验记录。
